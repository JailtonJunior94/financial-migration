# Relatório de Execução - Tarefa 8.0

## Tarefa

**8.0 - Implementar artefatos operacionais, CLI e rastreabilidade final**

Implementar a camada operacional final do pipeline: review artifacts sanitizados, progress store separado, comandos CLI por estágio, saída auditável e matriz de rastreabilidade ponta a ponta entre origem, consolidação, classificação e destino.

## Resumo da Implementação

Foram implementados stores atômicos para progresso operacional, review artifacts e bindings remotos; adapters de arquivo para execução offline dos estágios do pipeline; comandos CLI explícitos por estágio e utilitários operacionais; e a matriz de rastreabilidade ponta a ponta. A composição do runtime foi atualizada para tornar SQL Server e API destino opcionais, permitindo que comandos operacionais locais rodem sem um runtime completo.

### Arquivos criados

#### Stores atômicos

- `src/adapters/checkpoint/atomic-write.ts`
  - Utilitário de escrita atômica via arquivo temporário + rename, usado por todos os stores de arquivo.

- `src/adapters/checkpoint/file-progress-store.ts`
  - Implementação de `ProgressStorePort` com um arquivo JSON por escopo.
  - Suporta `write`, `read`, `list` e `reset` (escopo ou todos).

- `src/adapters/checkpoint/file-review-artifact-store.ts`
  - Implementação de `ReviewArtifactPort` persistindo issues como NDJSON sanitizado.
  - Redigir evidências sensíveis (`password`, `token`, `secret`, `cpf`, `cardnumber`, `card_number`).
  - Suporta `append`, `read`, `listScopes` e `reset`.

- `src/adapters/checkpoint/file-remote-binding-store.ts`
  - Implementação de `RemoteBindingStorePort` com um arquivo JSON por referência legada.
  - Permite múltiplas referências legadas apontando para o mesmo cartão remoto.

#### Rastreabilidade

- `src/domain/publication/traceability.ts`
  - Tipos `TraceabilityRow` e `TraceabilityMatrix`.
  - Função pura `buildTraceabilityMatrix` que mapeia `source ref -> fato canônico -> classificação -> publicação`, marcando inclusão, exclusão e bloqueios.

- `src/application/use-cases/build-traceability-matrix.ts`
  - Caso de uso que orquestra a construção da matriz com logging estruturado.

#### CLI e parsers

- `src/bootstrap/cli.ts`
  - Comandos de estágio offline: `pipeline:discover`, `pipeline:eligibility`, `pipeline:consolidate`, `pipeline:classify`, `pipeline:publish-cards`.
  - Comandos utilitários operacionais: `checkpoint:list/reset`, `progress:list/reset`, `review:list/reset`, `bindings:list/reset`, `traceability:matrix`.

- `src/bootstrap/cli-parsers.ts`
  - Validadores Zod para artefatos JSON passados aos comandos de estágio.

#### Runtime

- `src/bootstrap/composition/create-operational-runtime.ts`
  - Runtime leve que carrega apenas configuração, logger e stores locais, sem depender de SQL Server ou HTTP.

- `src/adapters/file/candidate-source-from-file.ts`
  - Adapter `CandidateSourcePort` que lê candidatos de arquivo JSON.

- `src/adapters/file/fact-reader-from-file.ts`
  - Adapter `FinancialFactReaderPort` que lê fatos de arquivo JSON.

- `src/adapters/file/category-catalog-from-file.ts`
  - Adapter `CategoryCatalogPort` que lê catálogo de categorias de arquivo JSON.

## Decisões e Observações

- A separação entre checkpoint legado, progress store, review artifacts e bindings remotos permite auditoria independente e reprocessamento seguro de cada estágio.
- O runtime operacional (`createOperationalRuntime`) não inicializa SQL Server nem HTTP, então comandos como `progress:list`, `review:list`, `bindings:list` e `traceability:matrix` funcionam sem credenciais de fonte/destino.
- Os comandos de estágio (`pipeline:*`) aceitam arquivos JSON como entrada, permitindo reproduzir o pipeline offline a partir de snapshots sanitizados produzidos por estágios anteriores.
- A matriz de rastreabilidade correlaciona `sourceRefs` com `factKeyHash`, status de consolidação/classificação, `remoteId` publicado e issues de bloqueio, atendendo aos requisitos de auditabilidade.
- Não foram introduzidas dependências novas.
