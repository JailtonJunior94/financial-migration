## Implementação entregue

### Domínio
- `src/domain/consolidation/eligibility.ts`
  - Normalização de texto para comparação case-insensitive e sem acentos (`normalizeText`).
  - Detecção do gatilho inicial "Jailton" (`nameContainsJailton`).
  - Modelagem de evidências e força de sinal (`signalStrength`, `isStrongSignal`).
  - Regra de segundo sinal forte (`hasStrongConfirmationSignal`).
  - Detecção de conflitos entre sinais fortes e o target user (`hasConflictingStrongSignals`).
  - Decisão de elegibilidade (`decideEligibilityScope`) com estados:
    - `eligible`
    - `blocked_no_strong_signal`
    - `blocked_inconsistent_target_user`
    - `blocked_not_active`
  - Exceção afirmativa explícita para `AccountControlDB.Accounts`.
  - Validação do target user (UUID, e-mail, telefone, status).
  - Helper `eligibilityStatusIsBlocking`.

### Aplicação
- `src/application/ports/legacy-user-candidate-source-port.ts`
  - Porta para carregamento de candidatos de usuário legado.
- `src/application/use-cases/build-eligibility-scope.ts`
  - Use case que orquestra a carga de candidatos e a decisão de elegibilidade.
  - Trata falhas da fonte como `ApplicationError` tipado (`SOURCE_READ_FAILURE`).
  - Propaga erros de domínio (`USER_NOT_ELIGIBLE`) sem perder contexto.
  - Registra logs estruturados de início, fim, elegível e bloqueado.

### Testes
- `test/domain/consolidation/eligibility.test.ts`
  - Testes unitários para normalização, matching de nome, força de sinal, segundo sinal forte, conflitos, regra afirmativa de Accounts e todos os estados de bloqueio.
- `test/application/build-eligibility-scope.test.ts`
  - Testes unitários do use case cobrindo caminho feliz, bloqueio, regra afirmativa e falha da fonte.
- `test/integration/eligibility-discovery-integration.test.ts`
  - Testes de integração mínimos para fluxo discovery controlado -> elegibilidade.
