# Relatório de Execução - Tarefa 1.0

## Tarefa

**1.0 - Fundar domínio e portas do pipeline financeiro**

Criar a base do novo pipeline em quatro estágios (`discovery`, `consolidation`, `classification`, `publication`) substituindo o modelo piloto genérico atual por value objects, estados e portas explícitas para o domínio financeiro.

## Resumo da Implementação

Foram criados os módulos de domínio `discovery`, `consolidation`, `classification` e `publication`, com os value objects centrais, tipos de dados, portas de aplicação e erros tipados necessários para os estágios seguintes do pipeline. Nenhuma query SQL, chamada HTTP real ou comando CLI final foi implementado, conforme escopo da tarefa.

### Arquivos criados

#### Domínio

- `src/domain/discovery/types.ts`
  - Tipos para metadados de tabelas legadas, amostras sanitizadas, cardinalidade e papéis semânticos (`FinancialDiscoverySnapshot`, `TableDiscoverySnapshot`, `SanitizedSample`, `TableSemanticRole`, etc.).
- `src/domain/consolidation/money-amount.ts`
  - Value object `MoneyAmount` com `minorUnits` (`bigint`), `scale` e `currency`.
  - Normalização de escala com arredondamento **half-even**.
  - Validação de moeda ISO 4217 e escala entre 0 e 18.
- `src/domain/consolidation/occurrence-date.ts`
  - Value object `OccurrenceDate` com `value`, `sourceField` e `fallbackUsed`.
  - Validação de datas ISO e rejeição de datas numericamente inválidas.
  - Função de fallback para `CreatedAt` quando não há data de fato.
- `src/domain/consolidation/canonical-fact-key.ts`
  - Value object `CanonicalFactKey` determinístico cross-source.
  - Contextos de pagamento (`credit-card`, `debit-card`, `bank-transfer`, `cash`, `unknown`) e parcelamento (`single`/`installment`).
  - Geração de hash SHA-256 canônica para idempotência.
- `src/domain/consolidation/installment-plan.ts`
  - Value object `InstallmentPlan` com `groupKey`, `currentInstallment` e `totalInstallments`.
  - Validação de parcelamento e função `isSinglePayment`.
- `src/domain/consolidation/types.ts`
  - Tipos de domínio consolidado: `LegacySourceRef`, `UserEligibilityScope`, `ConsolidatedCard`, `ConsolidatedTransaction`, `ReviewableIssue`, `PaymentMethod`, etc.
- `src/domain/classification/types.ts`
  - Tipos para taxonomia destino: `CategoryCatalog`, `CategoryDictionaryPage`, `ClassificationResult`, etc.
- `src/domain/publication/types.ts`
  - Tipos para publicação: `PipelineProgress`, `PublishableCard`, `PublishableTransaction`, `RemoteCardBinding`, `RemoteTransactionMatch`, `PublicationDecision`, etc.

## Decisões e Observações

- O value object `MoneyAmount` usa `bigint` para `minorUnits`, evitando `float` no domínio consolidado, conforme RF-36.
- A normalização de descrição em `CanonicalFactKey` usa `NFD` + remoção de marcas de combinação via `\p{Mn}+` (Unicode property), atendendo à regra de normalização de variações/acentos (RF-09) e evitando o alerta de lint `noMisleadingCharacterClass`.
- `OccurrenceDate` rejeita datas numericamente inválidas (ex.: `2026-02-30`) comparando componentes UTC da string parseada.
- Todas as portas são interfaces puras (contratos), sem acoplamento a adapters concretos, preservando a arquitetura hexagonal.
- Não foram introduzidas dependências novas.
